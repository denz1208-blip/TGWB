# 🔎 Telegram-бот: персональное отслеживание новых ШК в Google Таблице

> 📖 [Подробная установка на Linux-сервер](../INSTALL_LINUX.md) · [Главная страница репозитория](../README.md)

Бот периодически опрашивает Google Таблицу (через CSV-экспорт, **без API-ключей**)
и отдельно сообщает каждому пользователю только о **его** новых штрихкодах (ШК).

## 🆕 Что изменилось в версии 3.0.0

Раньше у всех пользователей был один общий список отслеживаемых ID, общая история
и общий список уже известных ШК. Теперь **у каждого пользователя Telegram свой аккаунт отслеживания**:

| Что | Было | Стало |
|-----|------|-------|
| ID сотрудников | общий список | свой список у каждого |
| Известные ШК | общий `seen_barcodes` | свой у каждого |
| Лента «Мои новые ШК» | общая | своя у каждого |
| Подписка на уведомления | общий `subscribers` | свои чаты у каждого |
| Последний запрошенный ID | общий | свой у каждого |
| Google-таблица | одна на всех | своя (команда `/sheet`) или общая |
| Белый список `/access` | общий | остался общим (это админы бота) |

Каждый аккаунт создаётся автоматически, когда пользователь впервые пишет боту
(даже просто `/start`). Ключ аккаунта — Telegram ID пользователя.

## Структура

```
tg_barcode_bot/
├── bot.py               # основной скрипт (aiogram 3), обработчики и мониторинг
├── sheet.py             # чтение Google Таблицы по публичной ссылке
├── state.py             # хранилище: аккаунты пользователей + белый список
├── config.py            # настройки из .env
├── state.json           # состояние (создаётся автоматически, НЕ хранить в git)
├── requirements.txt
├── .env.example         # шаблон настроек (токен НЕ вшит в код!)
├── barcode-bot.service  # unit-файл systemd
└── install.sh / reinstall.sh / update.sh / watchdog.sh
```

## Как это работает

1. Пользователь пишет боту → создаётся его личный аккаунт.
2. При первом опросе его таблицы все текущие подходящие ШК запоминаются как
   «уже известные» — старые строки не рассылаются.
3. Каждые `POLL_INTERVAL` секунд бот скачивает каждую используемую таблицу
   **один раз** и применяет к строкам фильтры каждого пользователя:
   * колонка «Статус» пустая;
   * ID из колонки «ID» есть в **его** списке (пустой список = все).
4. Новый ШК добавляется в его ленту и отправляется только в его чаты.
5. Всё сохраняется в `state.json` и переживает перезапуск.

Формат `state.json` (версия 2):

```json
{
  "version": 2,
  "allowed_users": [810321569],
  "accounts": {
    "810321569": {
      "username": "ivan",
      "employee_ids": ["112946"],
      "seen_barcodes": ["..."],
      "subscribed_chats": [810321569],
      "newest_notifications": {},
      "last_lookup_id": "112946",
      "sheet_url": "",
      "initialized": true,
      "created_at": "2026-11-21T12:00:00+00:00"
    }
  }
}
```

Старый `state.json` версии 1 при первом запуске автоматически конвертируется:
настройки получают администраторы из `ALLOWED_USER_IDS` / `/access`.

## Команды и кнопки

| Команда / кнопка | Действие |
|------------------|----------|
| `/start` | создать/открыть свой аккаунт, главное меню |
| 🆕 Мои новые ШК | ваши последние уведомления (хранятся 20) |
| 🔔 / 🔕 | включить/выключить **ваши** уведомления |
| 🔎 Поиск по ID | последние 20 ШК любого сотрудника в **вашей** таблице |
| 👥 Отслеживание | ваш список ID сотрудников |
| `/ids clear` | очистить **ваш** список (следить за всеми) |
| `/sheet` | показать вашу таблицу |
| `/sheet <ссылка>` | задать свою Google-таблицу |
| `/sheet reset` | вернуться к общей таблице из `.env` |
| `/status` | статус вашего аккаунта |
| `/id` | ваш Telegram ID |
| `/help`, `/version` | справка и версия/хеш кода |
| `/access ...` | белый список (только админы) |
| `/users` | список аккаунтов (только админы) |

Изменение таблицы через `/sheet` сбрасывает известные ШК: при первом опросе
новой таблицы текущие строки запоминаются и не присылаются как «новые».

### Как настроить своих сотрудников

* Отправьте ID (например, `112946`) → кнопки «🔎 посмотреть» / «➕ Отслеживать».
* `+112946 +5994498` — добавить несколько ID к своему списку.
* `112946, 5994498` — заменить свой список целиком.
* `/ids clear` — очистить свой список.

## Ограничение доступа

Список = `ALLOWED_USER_IDS` из `.env` + добавленные через `/access`.
Пока список пуст — доступ открыт всем. Неавторизованный пользователь получает
сообщение со своим ID, а админам приходит запрос с кнопками разрешения.

`/access` и `/users` доступны только администраторам.

## Установка и запуск (Linux)

### 1. Токен бота

[@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен.
Токен **не хранится в коде** — задайте его в `.env`:

```bash
cd tg_barcode_bot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
nano .env          # вставьте BOT_TOKEN (и при необходимости GOOGLE_SHEET_URL)
```

> ⚠️ Таблица должна быть открыта «Все, у кого есть ссылка — просмотрщик»,
> иначе CSV-экспорт не скачается.

### 2. Проверка

```bash
python bot.py
```

Напишите боту `/start`, затем `/status` — в ответе будут видны ваши ID и таблица.

### 3. Автозапуск (systemd)

```bash
sudo ./install.sh
sudo systemctl status barcode-bot
journalctl -u barcode-bot -f
```

Обновление с GitHub: `sudo ./reinstall.sh`. Скрипт сохраняет текущий `state.json`
(аккаунты пользователей не потеряются) и `.env`.

## Безопасность

* Если токен бота когда-либо попадал в репозиторий/чат — отзовите его в
  GitHub Settings → Developer settings → Personal access tokens (для токенов GitHub)
  или через [@BotFather](https://t.me/BotFather) (`/revoke`) для токена бота.
* `state.json` и `.env` добавляются в `.gitignore` — не коммитьте их.
* `/sheet` принимает только ссылки вида `.../spreadsheets/d/...` по http(s).
