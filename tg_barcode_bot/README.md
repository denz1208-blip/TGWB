# 🔎 Telegram-бот: отслеживание новых ШК в Google Таблице

Бот периодически опрашивает публичную Google Таблицу (через CSV-экспорт, **без API-ключей**)
и рассылает подписчикам сообщения о новых штрихкодах (ШК).

Работает на Linux (проверено на Python 3.10+).

## Структура

```
tg_barcode_bot/
├── bot.py               # основной скрипт бота (aiogram 3)
├── sheet.py             # чтение Google Таблицы по публичной ссылке
├── state.py             # хранение известных ШК и подписчиков (state.json)
├── config.py            # настройки из .env
├── requirements.txt
├── .env.example         # шаблон настроек
└── barcode-bot.service  # unit-файл systemd для автозапуска
```

## Принцип работы

1. При первом запуске бот запоминает **все текущие ШК** таблицы как «известные» (старые не рассылаются).
2. Каждые `POLL_INTERVAL` секунд скачивает таблицу через `export?format=csv&gid=...`.
3. Сравнивает с сохранённым списком (`state.json`) и присылает подписчикам новые ШК,
   **только если выполнены оба условия**:
   * колонка «Статус» в строке пустая;
   * ID сотрудника из колонки «ID» входит в ваш список отслеживания.
4. Интерфейс — кнопки (reply-клавиатура + inline), текст сообщений без HTML-разметки.

## Кнопки меню

| Кнопка | Действие |
|--------|----------|
| 🆕 Мои новые ШК | последние 10 присланных уведомлений (хранятся последние 20) |
| 🔔 Включить / 🔕 Выключить | подписка на уведомления для этого чата |
| 🔎 Поиск по ID | ввод ID сотрудника → **последние 20 его ШК** (с датами и статусами); последний запрошенный ID запоминается навсегда |
| 👥 Отслеживание | настройка списка ID сотрудников для уведомлений |
| ℹ️ Помощь | справка |

Также доступны команды: `/start`, `/subscribe`, `/unsubscribe`, `/status`,
`/ids clear` (очистить список отслеживания), `/id` (ваш Telegram ID), `/help`.

### Как настроить отслеживаемых сотрудников
* Отправьте боту просто ID (например, `112946`) — он предложит кнопки:
  **🔎 посмотреть ШК** или **➕ Отслеживать** (добавить в список уведомлений).
* `+112946 +5994498` — добавить несколько ID к текущему списку.
* `/ids clear` — очистить список (будут приходить ШК всех сотрудников с пустым статусом).
* Стартовое значение — `TARGET_EMPLOYEE_IDS` в `.env`; всё сохраняется в `state.json`
  и переживает перезапуск.

Подписаться могут любые чаты/группы, куда нажата кнопка «🔔 Включить» или `/start`.

## Установка и запуск (Linux)

### 1. Получите токен бота
Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен.

### 2. Настройте окружение

```bash
cd tg_barcode_bot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
nano .env          # вставьте BOT_TOKEN
```

> ⚠️ Таблица должна иметь доступ «Все, у кого есть ссылка — просмотрщик»,
> иначе бот не сможет её скачать. Ваша таблица уже открыта — проверять не нужно.

### 3. Запуск вручную (для проверки)

```bash
python bot.py
```

Затем найдите бота в Telegram и отправьте `/start`.

### 4. Автозапуск через systemd (продакшн) — одна команда

Токен бота уже вшит в `config.py` и `.env`, настраивать ничего не нужно:

```bash
sudo ./install.sh
```

Скрипт сам: установит зависимости, скопирует проект в `/opt/tg_barcode_bot`,
создаст venv, зарегистрирует сервис `barcode-bot` с автозапуском при загрузке
и перезапуском при падении, затем запустит бота.

Управление:
```bash
sudo systemctl status barcode-bot    # состояние
sudo systemctl restart barcode-bot   # перезапуск
sudo systemctl stop barcode-bot      # остановка
journalctl -u barcode-bot -f         # живые логи
```

<details>
<summary>Ручная установка (альтернатива)</summary>

```bash
sudo mkdir -p /opt/tg_barcode_bot
sudo cp -r . /opt/tg_barcode_bot
cd /opt/tg_barcode_bot
sudo python3 -m venv venv

```

## Настройки (.env)

| Переменная            | Описание                                                              | По умолчанию |
|-----------------------|-----------------------------------------------------------------------|--------------|
| `BOT_TOKEN`           | токен от @BotFather                                                   | — (обязательно) |
| `GOOGLE_SHEET_URL`    | ссылка на таблицу                                                     | ссылка из задачи |
| `POLL_INTERVAL`       | период опроса, сек                                                    | 60 |
| `BARCODE_COLUMN`      | имя колонки со ШК                                                     | `ШК` |
| `STATUS_COLUMN`       | колонка статуса; уведомления шлются только если она **пустая**        | `Статус` |
| `EMPLOYEE_ID_COLUMN`  | колонка с ID сотрудника в таблице                                     | `ID` |
| `TARGET_EMPLOYEE_IDS` | ID сотрудников через запятую — следить только за ними (пусто = все)   | пусто |
| `ALLOWED_USER_IDS`    | Telegram ID пользователей с доступом к боту, через запятую (пусто = всем) | пусто |
| `STATE_FILE`          | путь к файлу состояния                                                | `state.json` |

### Ограничение доступа (белый список)

Боту могут пользоваться только пользователи из белого списка. Список =
`ALLOWED_USER_IDS` из `.env` + те, кого добавили командой `/access add` (хранится в `state.json`).
Пока список пуст — доступ открыт всем.

Команды управления (без перезапуска):
```
/access                  — текущий список разрешённых
/access add 123456789    — разрешить пользователя
/access remove 123456789 — запретить
/access clear            — очистить добавленные через /access
/id                      — узнать свой Telegram ID
```
Когда список задан и незнакомец пишет боту — он получает «⛔ Доступ закрыт» со своим ID,
а всем разрешённым пользователям приходит запрос доступа с кнопками
«✅ Разрешить доступ / 🚫 Отклонить». Рассылка новых ШК тоже идёт только
разрешённым подписчикам.

### Фильтр уведомлений

Уведомление приходит, только если выполняются **оба** условия:
1. Колонка `Статус` в строке таблицы пустая.
2. Если задан `TARGET_EMPLOYEE_IDS` — `ID` сотрудника в строке входит в список.

Пример в `.env`:
```
TARGET_EMPLOYEE_IDS=112946,5994498
```
После изменения настроек перезапустите бота: `sudo systemctl restart barcode-bot`.

## Возможные доработки

- Уведомления об **изменении статуса** существующих ШК (сейчас шлются только новые).
- Голосовой/кнопки-инлайн вместо команд.
- Переход на Google Sheets API (service account), если закроете общий доступ к таблице.
